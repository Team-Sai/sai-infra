SAI Terraform 파일별·줄별 코드 안내서

현재 sai-infra 구성 소스를 그대로 포함하고, 모든 소스 줄 옆에 한국어 설명을 붙였습니다. 루트 입력에서 모듈로 값이 연결되고, 모듈 안 resource가 AWS 설계가 되며, outputs로 팀 연결 규격이 나오는 순서로 읽으세요.

실제 AWS 계정에 접속하거나 리소스를 생성하지 않았습니다. 따라서 실제 ID·주소·ARN은 없습니다.

처음 읽을 핵심 개념

Terraform 코드는 AWS 인프라의 설계도입니다. variables.tf는 입력과 기본값, 루트 main.tf는 모듈 간 연결, 모듈 안의 resource는 생성할 AWS 종류·설정, outputs.tf는 공유할 결과 이름을 뜻합니다. 코드를 작성했다고 AWS가 만들어지는 건 아닙니다.

입력 variables→루트 모듈 연결→모듈 resource→팀 output
VPC / AZ / subnet
VPC는 사설 네트워크, AZ는 리전 내 분리된 장애 영역, subnet은 AZ 내부 IP·경로 구역입니다. AZ마다 Public/App Private/Data Private 하나씩 두어 총 6개입니다.
Private / NAT
Public subnet은 Internet Gateway 경로를 사용합니다. App Private는 같은 AZ NAT로 외부 요청을 보냅니다. Data Private에는 인터넷 기본 경로가 없습니다. S3 Gateway Endpoint는 S3 경로를 NAT 밖으로 연결합니다.
EKS / Node / Pod
EKS control plane은 Kubernetes API를 관리합니다. Worker Node는 앱 Pod가 실행되는 EC2이며 Pod는 컨테이너 실행 단위입니다. AZ별 1대는 초기 배치이지 무중단 보장이 아닙니다.
모듈 variables
루트 변수는 팀의 기본 입력입니다. 하위 모듈 변수는 부모가 전달할 입력 타입을 선언합니다. module.network.vpc_id는 다른 모듈이 제공한 output을 가져옵니다.

검토하면서 반영한 수정

IMDS와 CNI 권한: 노드 IMDSv2 hop limit을 1로 낮췄고, VPC CNI 권한을 공용 노드 역할에서 분리해 kube-system/aws-node Pod Identity 역할로 연결했습니다.
SSM 터널: 임의 host/port를 전달하는 AWS 관리형 원격 포워딩 문서 권한을 빼고, 현재 EKS API의 TCP 443과 로컬 8443만 쓰는 Terraform 관리 문서를 추가했습니다.
Load Balancer Controller: 중복된 무조건 EC2 보안 그룹 ingress 변경 권한을 제거하고, 클러스터 태그 조건을 가진 기존 권한만 이용합니다. node SG에 해당 태그를 붙였습니다.
NetworkPolicy 준비: VPC CNI NetworkPolicy 엔진을 켰습니다. Kubernetes 팀이 Namespace default-deny와 DNS/DB/Redis 허용 정책을 배포하기 전까지 Pod별 격리가 완성된 것은 아닙니다.
남은 데이터 네트워크 범위: RDS/Redis SG가 EKS node SG 전체를 출발지로 허용합니다. 그 노드의 Pod가 접속을 시도할 수 있습니다. NetworkPolicy 적용 후에도 DB 계정 권한과 Redis IAM/ACL을 함께 제한해야 합니다.

SSM 대화형 셸은 CloudWatch Logs에 기록합니다. 포트 포워딩 터널 내부의 kubectl 요청/응답 내용은 기록하지 않습니다. 세션 시작 이벤트와 Kubernetes audit 로그는 별도 기록입니다.

순서대로 읽기

  1. 루트 versions.tf → variables.tf → locals.tf → main.tf에서 실행 조건·입력·모듈 연결을 봅니다.
  2. modules/network에서 VPC, AZ별 subnet, route table, NAT, S3 endpoint를 봅니다.
  3. modules/eks에서 Private API, worker, 애드온, IAM, Bastion/SSM을 봅니다.
  4. modules/data에서 MariaDB·Redis와 네트워크/인증 경계를 봅니다.
  5. modules/iam과 modules/storage에서 앱 권한·S3·ECR를 봅니다.
  6. 선택 호출형 modules/mock-bank, 루트 output, 샘플 값, README 순으로 읽습니다.

괄호·쉼표 같은 문법 줄도 건너뛰지 않고 설명합니다. 검색창은 파일명·코드·설명에서 찾고, 파일별로 접고 펼 수 있습니다.
